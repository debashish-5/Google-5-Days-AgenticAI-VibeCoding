===============================================
Google 5 Days VibeCodes 
===============================================

A modular AI assistant prototype built with Flask, LangChain, local FAISS indexes, and Groq. This project combines PDF ingestion, vector search, hybrid retrieval, and conversational generation into a single backend with a lightweight browser interface.

---

## Project overview

This repository contains two Flask-based backend implementations and a single-page UI for an AI teaching assistant experience. The app is designed to retrieve context from local PDF documents and vector indexes, then answer user questions using a connected language model.

The system supports:
- local document ingestion from `documents/`
- chunking and embedding with `HuggingFaceBgeEmbeddings`
- multiple FAISS index formats: HNSW, PQ, IVF, IVFPQ
- hybrid retrieval using BM25 and FAISS
- optional Pinecone vector search support
- optional Tavily web search integration
- Groq conversational language model support via `ChatGroq`

---

## Key files

- `app.py` - main application with document loader, retriever classes, hybrid search, Pinecone retrieval, and `/chat` endpoint logic.
- `app_new.py` - simplified backend implementation that loads a selected FAISS index and generates answers with the Groq model when available.
- `templates/index.html` - modern chat UI served by Flask.
- `documents/` - source PDF documents used for building vector search context.
- `HNSW_faiss/`, `PQ_faiss/`, `IVF_faiss/`, `IVFPQ_faiss/` - local FAISS indexes for retrieval experiments.
- `*.ipynb` - exploratory notebooks for indexing, search, and API testing.

---

## Architecture

1. Local PDF documents are loaded by `PyPDFDirectoryLoader`.
2. Documents are split into chunks using `RecursiveCharacterTextSplitter`.
3. Embeddings are generated with `sentence-transformers/all-MiniLM-L6-v2`.
4. Chunks are indexed with FAISS and optionally stored in a Pinecone-equipped index.
5. User queries pass through a selected retriever, and the response is generated by `ChatGroq` or a fallback preset.
6. The frontend sends requests to `/chat` and renders answers with context sources.

## Setup

1. Create a Python environment.

   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   ```

2. Install dependencies.

   ```bash
   pip install flask python-dotenv langchain-core langchain-groq langchain-classic langchain-community langchain-text-splitters openai requests langsmith
   ```

3. Create a `.env` file with API keys.

   ```text
   GROQ_API_KEY=your_groq_api_key
   PINECONE_API_KEY=your_pinecone_api_key
   TAVILY_API_KEY=your_tavily_api_key
   ```

4. Ensure the `documents/` folder contains PDF files and the index folders exist.

---

## Running the app

Use one of the backend entrypoints.

```bash
python app_new.py
```

or

```bash
python app.py
```

Then open `http://127.0.0.1:5000/` in a browser.

---

## Usage

- The UI loads from `templates/index.html`.
- The `/chat` endpoint accepts JSON payloads with `message` and `vector_store`.
- Supported vector store values in `app_new.py`:
  - `faiss-hnsw`
  - `faiss-ivf`
  - `faiss-ivfpq`
  - `faiss-pq`
  - `pinecone`

If no Groq key is available, the app returns a fallback message with a relevant context snippet.

---

## Notes

- `app_new.py` is a cleaner backend implementation focused on local FAISS retrieval and prompt-based response generation.
- `app.py` includes additional agent tooling, retriever classes, and hybrid search examples.
- The project is intended for experimentation and local development, not production deployment.
